## 1. 背景

AR014 用 int8 单行 `needs_reasoning` 门控把 LCPT_CASC_FAST 做到 P50 2.42s。
门控仍按 Laya `max_len=512` 处理 state，是剩余成本的重要部分。

真实探测（shared-prefix 12 题，int8 门控）：

| 窗口 | 命中 reasoning | 门控均值 |
| --- | --- | --- |
| 192 | 9/12 | 456ms |
| 256 | 9/12 | 639ms |
| 320 | 8/12 | 867ms |
| **384** | **12/12** | **1046ms** |
| 448 | 10/12 | 1273ms |
| 512 | 10/12 | 1513ms |

窗口 384 在目标负载上命中率最高且比 512 快约 30%。

## 2. 目标

- 新增 `decision_long_context_gate_tokens`（默认 384，0=沿用完整 512）。
- 仅影响 int8 门控后端的 state 窗口；fp32 RDMP 兜底仍用完整窗口。
- 未命中/窗口过短导致 no_reasoning → 完整 AR014 回退，路由不变。
- 真实验证：shared 路由一致、质量/输出不降、联合端到端 CI 下界 >0。

## 3. 功能需求

| ID | 需求 | 验收 |
|----|------|------|
| FR15-1 | `decision_long_context_gate_tokens` 默认 384，0 表示不额外截断 | 单测 |
| FR15-2 | int8 门控后端使用该窗口；fp32 兜底不受影响 | 单测/集成 |
| FR15-3 | 窗口缩短只可能更保守（FULL）或回退，不产生更便宜路由 | 集成 |
| FR15-4 | 真 shared 12 题门控命中与路由一致 | assets+slow |
| FR15-5 | 联合矩阵相对 AR014 有正收益才 adopt | matrix |

## 4. 非功能需求

| 类型 | 指标 | 要求 |
|------|------|------|
| 性能 | 门控均值 | 相对 512 窗口 ≥20% 降低 |
| 安全 | 激进翻转 | 0 |
| 兼容 | 0/缺 int8 | 与 AR014 一致 |
| 测试 | 后端 | 无 mock |

## 5. 约束

- 窗口按 Laya token 计；短于 head+options 时由现有构建逻辑拒绝并回退。
- 默认 384 仅对 `> decision_long_context_tokens` 的 state 生效。
